# Design Principles - {{PROJECT_NAME}}

이 문서는 제품 전반의 공통 디자인 원칙, 접근성·반응형 기준, UI 기술 및 컴포넌트 재사용 규칙을 정의합니다. UI 작업 시 [PRD 작성 규칙](AGENTS.md)과 해당 기능 PRD의 `User Experience`를 함께 읽습니다.

## Scope

- 공통 원칙과 공유 UI 구현 규칙만 관리합니다. 앱의 실제 기술 스택과 기존 디자인을 확인한 뒤 구체화하며, 이 템플릿만으로 특정 프레임워크나 스타일을 채택하지 않습니다.
- 화면 구성, 버튼 문구, 사용자 흐름, 화면별 로딩·빈 상태·오류·성공 상태는 기능별 PRD의 `User Experience`에 작성합니다.
- 기술 선택의 근거와 대안은 ADR에, 구현·검증 결과는 plan step에 기록합니다. 이 문서에 Current State, 완료 일지, 스크린샷 또는 테스트 이력을 누적하지 않습니다.

## Common Design Principles

- 정보의 중요도와 사용자 작업 순서가 시각적 계층에 드러나도록 합니다.
- 같은 의미와 동작에는 일관된 표현과 상호작용을 사용합니다. 기존 패턴을 우선 재사용합니다.
- 정보 밀도는 실제 작업에 맞추고, 장식보다 가독성과 주요 행동의 식별을 우선합니다.
- 사용자 입력을 보존하고 작업 진행·결과·복구 방법을 인지할 수 있는 피드백을 제공합니다.
- 모션은 변화와 관계를 이해시키는 용도로만 사용합니다.

## Accessibility

- 의미에 맞는 HTML과 접근 가능한 컴포넌트를 사용하고, 입력의 이름·설명·오류를 보조 기술로 인지할 수 있게 연결합니다.
- 주요 작업은 키보드로 수행 가능해야 하며 포커스가 보이고 논리적으로 이동해야 합니다. 대화상자 등 임시 UI는 포커스 진입·복귀를 관리합니다.
- 색상만으로 의미를 전달하지 않고 읽기 가능한 대비를 확보합니다.
- 텍스트 확대와 모션 감소 설정을 존중합니다.

## Responsive Behavior

- 화면 크기가 달라도 핵심 정보와 작업을 사용할 수 있도록 동등한 기능을 제공합니다.
- 콘텐츠와 작업 특성에 맞춰 레이아웃을 조정하며, 특정 기기 크기나 화면별 배치를 이 공통 문서에서 고정하지 않습니다.
- 텍스트 확대, 긴 문구, 좁은 화면에서 내용 잘림과 의도하지 않은 가로 스크롤을 피합니다.
- 기능별 PRD에서 필요한 화면 크기와 입력 방식의 검증 시나리오를 구체화합니다.

## UI Framework and Component Reuse

- 앱 구성 시 실제로 사용하는 UI 프레임워크, 스타일링 방식, 접근성 프리미티브 및 공통 컴포넌트 경로와 각 책임을 이 절에 기록합니다. 확인되지 않은 라이브러리를 기본값으로 단정하지 않습니다.
- 새 의존성이나 별도 UI 체계를 도입하기 전에 기존 공유 컴포넌트와 토큰을 확인합니다.
- 같은 의미의 컴포넌트는 공유 구현과 변형 규칙으로 재사용하고, 기능 전용 구성은 해당 기능 가까이에 둡니다.
- 공통 컴포넌트의 접근성·상태·반응형 규칙은 공유 계층에서 유지합니다. 구체적인 화면 요구사항은 기능 PRD가 소유합니다.
